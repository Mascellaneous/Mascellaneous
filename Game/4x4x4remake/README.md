# SWF 遊戲現代化重製版：4×4×4 立體連珠

本目錄是使用者提供的 `game.swf` 之**功能性重製版**。成品以原生 **HTML、CSS、JavaScript 與 Canvas 2D** 完成，不使用框架、套件管理器、CDN、建置工具或外部 API。直接以瀏覽器開啟 `index.html` 即可遊玩；若瀏覽器因本機檔案安全策略不載入 SVG，可在目錄中啟動任一靜態檔案伺服器後開啟。

> 重製目標是將 Flash 遊戲的規則、視覺比例與互動模式轉譯到現代瀏覽器，而不是把 SWF 直接嵌入或模擬執行。原始程式與資產只作為逆向分析和視覺重用依據。

## 遊戲方式

這是一個 **4 × 4 × 4 的立體連珠**。紅方先行，紅、藍雙方輪流選擇一個空的立方體格。任一方只要沿直線佔滿四格便獲勝；直線可以位於三個主軸、任一平面對角線，或任一空間對角線上。

原始 SWF 的互動方式為：先點擊一條 i、j 或 k 的「層面控制線」，系統會只顯示該 4×4 平面上的候選立方體，再點擊其中一格。本重製版保留了相同的兩段式選擇，只是把控制線改為可讀性較高的軸向與層數按鈕。

| 操作 | 滑鼠／觸控 | 鍵盤 |
| --- | --- | --- |
| 選擇軸向 | 點擊 `i 軸`、`j 軸` 或 `k 軸` | `I`、`J`、`K` |
| 選擇層數 | 點擊 1–4 層按鈕 | `1`–`4` |
| 放置立方體 | 點擊被點亮的空格 | 將游標停在空格後按 `Enter` |
| 暫停／繼續 | 點擊暫停按鈕 | `Esc` 或空白鍵 |
| 重新開局 | 點擊重新開局／重玩按鈕 | `R` |

## 逆向分析摘要

原始檔是 Flash 9 的壓縮 SWF（CWS），舞台尺寸為 **550 × 350 px**，主時間軸有 430 個影格。開場時間軸先顯示標誌與棋盤出現動畫；抵達最後一格後，ActionScript 3 動態建立 64 個可點選方塊與 12 個層面控制線。

反編譯的三個核心類別分工如下。

| 原始類別 | 作用 | 重製對應 |
| --- | --- | --- |
| `Cube.as` | 計算等角投影座標、處理點擊、記錄玩家佔領狀態、檢查四連線。 | `app.js` 的 `pointFor()`、`place()`、`isWinningMove()`。 |
| `Grid.as` | 用兩個 32 位元整數記錄各玩家在 64 格中的位元集合。 | 使用 64 格 JavaScript 陣列，值為 `null`、`red` 或 `blue`，方便繪製與除錯。 |
| `Line.as` | 選取 i、j、k 軸之一的 4×4 平面，隱藏其他未佔領格。 | `activePlaneIndices()` 與平面控制按鈕。 |

### 原始座標與等角投影

原始程式對索引 `index = i × 16 + j × 4 + k` 使用下列常數：`ORG_X = 170`、`ORG_Y = 175`、`R = 40`。重製版沿用同一投影公式，因此棋盤在 550×350 畫布中的位置與相對比例保持一致。

```text
x = 170 + round((j − k) × 40 × √3 / 2)
y = 175 + round((j + k − 2i) × 40 / 2)
```

在投影平面上，空間對角線的若干格會視覺重疊；因此必須先限制可點選格至單一 4×4 平面，才能讓命中測試沒有歧義。這也是原始遊戲需要先選層的實際原因。

### 勝利線判定

原始 ActionScript 針對剛落下的方塊檢查七類方向：三個主軸、三組平面對角線，以及空間對角線。重製版改採一般化的方向列舉：先產生所有正向規範化的方向向量，僅從「前一格超出棋盤、第四格仍在棋盤」的起點建立四格線段，從而得到無重複的所有獲勝線。

```text
for each direction (di, dj, dk):
  for each valid start (i, j, k):
    line = [(i, j, k), (i+di, j+dj, k+dk), ... 共四格]
    若 line 的四格都屬於本回合玩家，則獲勝
```

這種寫法不依賴硬編碼座標，也可直接延伸至不同棋盤尺寸或連線長度。與原版只輸出 `trace("Red win!!!")` 相比，重製版會停止輸入、以銅色圈標示獲勝四格並在介面上顯示結果。

## 原始資產的使用情況

| 檔案 | 來源 | 在重製版的用途 |
| --- | --- | --- |
| `assets/original-logo.jpg` | SWF 的唯一內嵌 JPEG（匯出 Character ID 12） | 顯示於頂端識別區。 |
| `assets/original-board.svg` | 原始 SWF 向量形狀匯出 | 在 Canvas 中直接作為棋盤底圖。 |
| `assets/original-cube.svg` | 原始 SWF 向量形狀匯出 | 在 Canvas 中直接繪製選取平面的可落子提示。 |

原始 SWF 的標籤清單不包含 `DefineSound`、`StartSound` 或串流音訊標籤，因此**沒有可擷取的獨立原始音效**。本重製版沒有擅自新增替代配樂或音效，以免誤導為原作內容。

## 技術設計

Canvas 的內部尺寸固定為原始舞台大小 550×350，以避免高 DPI 或 CSS 響應式縮放改變遊戲座標。CSS 只改變 Canvas 的顯示尺寸；滑鼠座標會依 `getBoundingClientRect()` 反向換算回原始舞台座標。這使桌面與行動裝置都能共用完全相同的命中測試。

遊戲狀態被維持在一個 64 格陣列中。每次操作只更新陣列、活動平面、目前玩家、勝利線與暫停旗標，接著由 `draw()` 完整重繪畫布。因為畫面元素非常少，完整重繪比保留殘留影格或管理多層 DOM 更可靠，也不會造成可見效能問題。

| 模組 | 責任 | 關鍵實作 |
| --- | --- | --- |
| 狀態 | 回合、棋格、平面、暫停與結局 | `cells`、`currentPlayer`、`activeAxis`、`activeLayer` |
| 投影 | 將 `(i,j,k)` 轉為畫布座標 | `pointFor()` |
| 命中測試 | 只在當前 4×4 平面找最近的空格 | `findCellAt()` |
| 視覺 | 使用原始 SVG 加上 Canvas 上色立方體 | `drawOriginalCube()`、`drawPlayerCube()` |
| 規則 | 生成並比對所有四格直線 | `buildWinningLines()`、`isWinningMove()` |
| 可存取性 | 焦點、即時狀態公告、鍵盤與減少動態效果 | `aria-live`、`keydown`、`prefers-reduced-motion` |
