# Structure：立體過四關

## 交付架構

使用者可直接開啟根目錄的 `index.html`。它包含所有 HTML、CSS、SVG 與 JavaScript，沒有 CDN、套件、遠端字型或資料請求；所有遊戲狀態只存在於瀏覽器記憶體。`README.md` 解釋規則、操作、AI 策略與關鍵演算法。

WebDev 預覽殼層則在 `client/src/` 顯示同一份設計語言，並以生成的背景與標誌強化開發中的視覺 QA；根目錄的單檔版本始終是 GitHub 專案的可攜式正式產物。

## 單檔模組責任

| 邏輯區塊 | 責任 |
|---|---|
| `GameState` | 持有 64 格盤面、目前玩家、模式、難度、歷史步驟、勝利線及是否鎖定輸入。 |
| `LineEngine` | 依 13 個正規化方向向量產生 76 條長度四的線段，並由最近落子快速檢查勝負。 |
| `Strategist` | 實作 AI 的即勝、即時阻擋、中心偏好、線段潛力與穩定平手破局。 |
| `BoardRenderer` | 以語意化按鈕產生四層 4×4 格子、座標、預覽棋子、落子動畫與勝利光帶。 |
| `UIController` | 同步回合板、設定視窗、說明視窗、鍵盤操作、音效、減少動畫與 `?demo` 自動示範。 |

## 資料模型

棋格座標用 `(x, y, z)` 表示，三個維度均為 `0…3`。儲存鍵是 `"x,y,z"`，盤面值為 `0`（空）、`1`（訊號青綠）或 `2`（珊瑚橘）。勝利線為四個鍵值陣列；歷史紀錄保留落子鍵、玩家與回合前後資訊，供悔棋安全還原。

## 狀態轉換

`idle → placing → checking → (idle | won | draw)` 是每一步的核心狀態。電腦模式下，玩家落子後先檢查是否結束，未結束即進入短暫 `thinking` 鎖定；AI 完成後回到相同檢查流程。悔棋在雙人模式回退一步，在電腦模式優先回退最近兩個完整回合。

## 資產提示

最終遊戲以 CSS 漸層、SVG 路徑與原生圖示完成核心材質，不需載入檔案。生成的「晶格指揮中心」影像只由 WebDev 預覽殼層使用，並不改變單檔版本的離線能力。
