# 瀏覽器驗證紀錄

## 初始載入

已於開發預覽的 `/simon.html` 載入單檔成品。畫面顯示深色圓形機殼、綠紅藍黃四色扇形按鍵、中央黃色開始鍵、目前分數與最佳分數。四個色塊具備可辨識的無障礙名稱，開始鍵可由瀏覽器互動清單找到。

## 啟動第一回合

按下中央開始鍵後，按鈕文字切換為「重來」，顯示狀態為「你的回合」，狀態文案為「你的回合：重現剛才的節奏。」這證實非同步播放階段完成後，彩色按鍵進入可輸入的玩家階段；分數仍為 00，符合第一組訊號尚未被完成的規則。

## 執行中狀態

透過頁面內的測試介面取得第一回合狀態：`phase` 為 `player`、`sequence` 與 `expected` 均為 `[2]`、`score` 為 `0`、`highScore` 為 `0`。此結果與畫面顯示一致。一次將兩個敘述以分號串接的非同步主控台測試被頁面評估器拒絕；後續測試改以單一表達式進行，並不影響遊戲程式本身。

## 正確輸入與下一回合

送出正確的第一步 `2` 後，最高分更新為 `1`，目前分數更新為 `1`，並生成兩步序列 `[2, 0]`。在機器播放結束後，`phase` 回到 `player`，且 `expected` 為同一個兩步序列 `[2, 0]`。這驗證了正確輸入、最高分保存、序列擴充與深複製佇列的流程。

## 錯誤輸入

在第二回合故意輸入錯誤的首碼 `1` 後，內部狀態轉為 `lost`；可見畫面同步顯示「模式：失誤」與「順序不對。本局完成 1 組；按『開始』再試一次。」開始按鈕恢復為「▶ 開始」，目前與最佳分數都維持 `01`。這驗證了錯誤收束、按鍵鎖定及重新開始入口。

## 最終資產預覽

重啟靜態預覽後，最終 `simon.html` 已正常載入：可見四個顏色按鍵、中央開始鈕、待命狀態、目前分數與先前保存的最佳分數。這次載入使用的是最終交付的 `assets/sound-54.mp3` 至 `assets/sound-57.mp3` 相對參照；命令列檢查已驗證這四個檔案皆可由 MP3 解碼器讀取。

## 最終版首回合

在最終預覽中按下開始後，畫面切換為「你的回合」，而頁面執行狀態為 `phase: player`、`sequence: [3]`、`expected: [3]`、`score: 0`。這確認了相對原始音效資產版本並未破壞遊戲狀態機。

送出正確首碼 `3` 後，最終版將 `score` 更新為 `1`，並新增一個訊號為序列 `[3, 0]`。在第二輪機器播放結束後，狀態再度為 `player`，`expected` 則是獨立而內容相同的 `[3, 0]`。這完成了最終交付版本的成功路徑驗證。
