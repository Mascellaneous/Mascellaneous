# 立體過四關

> **把四條線，藏進同一個空間。**

「立體過四關」是一款無相依性的 **4 × 4 × 4 空間連四**策略遊戲。它把熟悉的井字棋／連線概念延伸到三個維度：棋子不會受重力影響，玩家可在 64 個任意空格落子；只要讓自己的四枚訊號在任意直線方向相連，即獲得勝利。

本專案的正式交付物是根目錄的 [`index.html`](./index.html)。該檔案內嵌所有 HTML、CSS、SVG 與 JavaScript，不使用套件、CDN、遠端字體、圖片或 API；下載後以瀏覽器直接開啟即可遊玩。

| 項目 | 說明 |
|---|---|
| 遊戲尺寸 | 4 × 4 × 4，共 64 個可落子位置 |
| 勝利條件 | 任意方向連成 4 枚相同訊號 |
| 勝利路徑 | 共 76 條，包含軸向、平面對角線與體對角線 [1] |
| 對局模式 | 對戰電腦、同機雙人 |
| 電腦強度 | 輕鬆、戰術 |
| 執行需求 | 支援現代 JavaScript 的桌面或行動瀏覽器 |

## 快速開始

將整個專案下載後，直接雙擊 `index.html`，或以瀏覽器的「開啟檔案」功能載入它即可。不必安裝 Node.js，也不必啟動本機伺服器。若要在本專案的開發環境中預覽，則可執行 `pnpm dev`，並開啟終端顯示的網址。

瀏覽器網址附加 `?demo` 參數時，遊戲會展示一段固定的自動對局，用來快速檢視棋子落下與勝利線效果。例如，在開發預覽可使用 `/?demo`；單檔版本也可以 `index.html?demo` 的方式透過瀏覽器開啟。另可使用 `?view=iso`、`?view=reverse` 或 `?view=sheets` 直接指定立體、反向或分層的初始視角，便於教學、分享與局勢檢查。

## 遊戲規則

棋盤由四個 4 × 4 平面堆疊而成，標示為 `L1` 至 `L4`。每一個格點用字母、數字與樓層表示，例如 `C2 · L3` 代表第 3 層的 C 欄、2 列。玩家一使用**訊號青綠**，玩家二使用**珊瑚橘**；雙人模式中兩人輪流落子，電腦模式中第二位由 AI 操作。

勝利並不只出現在平面的橫、直或斜線。四枚訊號也可以沿樓層方向排列，或沿著穿過立方體的斜線排列。這是本作的主要策略差異：一枚棋子往往同時參與多個平面與空間方向的威脅。

| 方向類型 | 數量 | 構成方式 |
|---|---:|---|
| 三條座標軸 | 48 | 每個軸有 16 條長度四的直線；合計 `3 × 16`。 |
| 三個平面上的對角線 | 24 | 每個座標平面各有 8 條；合計 `3 × 8`。 |
| 穿越立方體的體對角線 | 4 | 由一個角一路穿過中心至對角。 |
| **合計** | **76** | 程式以方向向量動態產生並驗證所有路徑。 |

## 操作方式與對局輔助

直接點選任一空格即可落子。棋子可落在任何尚未佔用的位置，不會向下掉落；落子後，狀態面板會顯示目前回合與最後一次操作的座標。棋盤上緣的 `VIEW` 控制提供三種閱讀方法：「立體」維持原本等角堆疊、「反向」從另一側檢查被遮蔽位置、「分層」把四個 4 × 4 平面拆成 2 × 2 小圖。在「立體」或「反向」視角中，可於棋盤區域以滑鼠或單指拖曳，調整上／下與左／右觀察角度；`↺` 按鈕可立即回到標準角度。棋盤下方的 `ALL` 與 `L1–L4` 按鈕則可在任何視角中聚焦單一樓層，其他樓層會淡化。

| 功能 | 位置 | 行為 |
|---|---|---|
| 棋盤視角 | 棋盤上緣 `VIEW` | 在立體、反向與分層圖之間切換；分層圖最適合辨認棋子所在的精確平面。 |
| 自由旋轉 | 立體／反向視角中的棋盤 | 以滑鼠或單指拖曳旋轉觀察角度；垂直傾角限制在 ±24°、水平旋轉限制在 ±32°，以保留棋格可讀性。 |
| 勝利線提示 | 停留在已落下棋子上 | 高亮該棋子參與、且未被對手阻斷的所有四格路徑；距離完成僅差一子的路徑以較粗虛線標示。 |
| 對局模式 | 右側「對局模式」 | 切換對戰電腦或同機雙人，並重置本次分數。 |
| 電腦強度 | 右側「電腦強度」 | 「輕鬆」較具探索性；「戰術」優先處理勝利與防守。 |
| 開局訊號 | 右側下拉選單 | 可指定玩家一或玩家二／電腦先行。 |
| 悔棋 | 右側「悔棋」 | 雙人模式退回一手；電腦模式盡量退回一個完整回合。 |
| 規則與設定 | 頁首圓形按鈕 | 顯示規則，或調整音效、減少動態效果及分數。 |
| 鍵盤 | `Tab`、`Enter`／`Space` | 以焦點選取棋格後落子；`Esc` 關閉視窗；`R` 重新開始。 |

> 電腦先行的第一枚棋子屬於已成立的開局狀態，因此不能單獨以悔棋移除；重新開始可重新選擇先行方。這項限制避免 AI 對局在沒有玩家前一手可回復的情況下，產生不一致的回合狀態。

## 電腦對手機制

AI 刻意採取可解釋、低延遲的策略評分，而非進行成本較高的完整博弈樹搜尋。這使它在 64 格盤面上能迅速作答，也讓不同強度有明顯的遊戲感差異。

在「戰術」模式中，AI 會依序檢查自己是否能立即連四、玩家是否有下一手連四威脅、各空格與棋盤中心的距離，以及該空格參與的未受敵方阻斷勝利線數量。相同分數時，以極小的隨機值打破平手，避免每局走出完全一致的棋譜。「輕鬆」模式維持相同的立即勝利與必要阻擋，但在中盤更常從可行候選點中探索。

| 優先順序 | 戰術模式行為 |
|---:|---|
| 1 | 立即落下可讓 AI 連成四的棋子。 |
| 2 | 阻擋玩家下一手可連成四的空格。 |
| 3 | 評估中心位置，讓單一棋子能參與更多方向。 |
| 4 | 評估可延伸、且未被對手佔據的勝利線。 |
| 5 | 對等分候選點做微量隨機平手破局。 |

## 技術設計

### 單檔與離線原則

根目錄 `index.html` 是本專案唯一必要的遊戲檔。其 CSS 放在 `<style>`，邏輯放在 `<script>`，圖示與勝利軌跡使用內嵌 SVG；包含背景雜訊在內的紋理也以 `data:` URI 處理。程式已掃描確認它不含外部網路資源，故即使在沒有網路連線的裝置上也可遊玩。[2]

為利開發環境的展示，`client/` 內另有一個前端預覽殼層；它使用生成的品牌背景與圖標，但**不影響**正式單檔交付物的離線性。若只需分享遊戲給他人，請直接使用根目錄的 `index.html`。

### 勝利線產生與判定

程式不以人工列舉 76 條線段，而是掃描 3D 格點並使用 13 個正規化方向向量。對於每一個起點 `(x, y, z)` 與方向 `(dx, dy, dz)`，只有當延伸三格後仍在盤內時，程式才建立一條候選線。方向向量只保留第一個非零分量為正的半邊方向，因此反方向不會產生重複線段。

每一次落子後，系統只檢查「剛落下的那個位置」所參與的候選線，而不必重新掃描整個棋盤。若其中一條線的四格都等於目前玩家，遊戲即將該線記入 `winning` 狀態，透過 SVG 將第一格連到最後一格，並以金黃色強調四個獲勝棋子。[1]

```text
例如：方向 (1, 1, 1)

(0,0,0) → (1,1,1) → (2,2,2) → (3,3,3)

這條路徑是「體對角線」；它和所有其他方向都由同一套規則生成。
```

### 狀態與渲染責任

遊戲以一個 `Map` 保存盤面，鍵值採用 `"x,y,z"` 格式，值為 `0`（空）、`1`（玩家一）或 `2`（玩家二）。歷史紀錄保存每一手的座標與玩家，供悔棋安全還原。`renderBoard()` 重新建立四個語意化棋盤層；每個空格是可聚焦的 `<button>`，所以滑鼠、觸控與鍵盤使用的是同一條操作路徑。

| 模組概念 | 在 `index.html` 中的責任 |
|---|---|
| `GameState` | 盤面、回合、模式、歷史、分數、輸入鎖定與勝利結果。 |
| `LineEngine` | 方向向量、76 條勝利線與落子後的快速判定。 |
| `Strategist` | 立即勝利、阻擋、中心評分、路徑潛力與平手破局。 |
| `BoardRenderer` | 以四個半透明平面、棋子、座標與 SVG 勝利線呈現 3D 棋局。 |
| `UIController` | 模式設定、對話框、提示訊息、音效、動態效果與 `?demo`。 |

### 視覺與無障礙設計

介面採用「晶格指揮中心」的資訊美學。深藍灰背景降低環境干擾；青綠與珊瑚形成明確的玩家對比；金色僅用於已完成連線。四層棋格使用不同高度、透明度與座標標籤來傳遞 Z 軸，而不是以大量裝飾取代空間閱讀。

所有棋格都有描述目前座標與佔用狀態的 `aria-label`，可被鍵盤焦點依序選取。動態效果使用短距離轉換，並同時支援系統的 `prefers-reduced-motion` 偏好與遊戲內的「減少動態效果」開關。提示音只在使用者操作後建立音訊內容，避免瀏覽器的自動播放限制。

## 驗證與開發指令

專案包含不依賴第三方測試套件的規則驗證腳本。它會生成與正式遊戲相同的 76 條勝利線，逐條驗證線段長度、盤內邊界、唯一性，以及所有完整勝利線都能被辨識。

```bash
node scripts/verify-game.mjs
```

開發預覽的 TypeScript 與生產建置可使用下列命令；這些命令驗證的是額外的預覽殼層，並非執行單檔遊戲所必需的前置條件。

```bash
pnpm check
pnpm build
```

本次交付已通過規則測試、離線資源掃描、TypeScript 檢查、生產建置、桌面預覽與手機寬度預覽。生產建置對預覽殼層提出單一大型程式區塊的提示；這是模板既有 UI 元件集合造成的體積警告，並不影響根目錄無相依 `index.html` 的直接使用。

## 授權與延伸

本專案以 `package.json` 所標示的 MIT 授權釋出。若要延伸玩法，建議先保留 `LineEngine` 的方向向量策略，並在新規則加入後同步擴充 [`scripts/verify-game.mjs`](./scripts/verify-game.mjs) 的案例；這能避免新增棋盤尺寸、障礙格或計時規則時破壞三維連線判定。
